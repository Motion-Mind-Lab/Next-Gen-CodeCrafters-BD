<h1 id="community-rules-overview">Community & GitHub Engagement Rules</h1>

Learn how to participate in code reviews, create technical issues, and engage in meaningful discussions to earn up to 50 activity marks in the bi-monthly league.

---

<h2 id="github-guidelines">1. Valid GitHub Issues & Code Review Guidelines</h2>

Up to 50 marks of your overall league tally depend on your active technical engagement on GitHub repositories. Submissions and interactions are closely inspected to ensure high engineering value.

<h3 id="review-standards">Actionable Code Review Criteria</h3>

* **Constructive Code Reviews:** Leaving reviews on peer repositories that focus on performance improvements, memory leak prevention, state management optimization, or architectural bugs.
* **Structured Bug Reports & Issues:** Filing GitHub issues with clear reproduction steps, expected versus actual behavior, and code snippets or screenshots.
* **Meaningful Pull Requests (PRs):** Submitting pull requests to peer repositories or open-source projects that resolve existing issues, optimize code, or enhance documentation.

<h2 id="discussions-vs-spam">2. Meaningful Group Discussions vs. Spamming</h2>

Community activity is designed to encourage knowledge sharing, technical debugging, and constructive peer support—not artificial point farming.

<h3 id="engagement-rules">Engagement Distinction</h3>

| High-Signal Engagement (Earns Points) | Low-Effort / Spamming (0 Points / Penalty) |
| :--- | :--- |
| Writing detailed technical posts about engineering challenges solved in your project. | Posting generic comments like "Nice project!", "LGTM!", or "Great job!" without code feedback. |
| Answering peer technical questions or helping debug code in official community forums. | Mass-commenting or bumping threads repeatedly to artificially boost activity metrics. |
| Sharing research notes, benchmarks, or architectural trade-offs. | Posting non-technical memes, promotional referral links, or unrelated content. |

<h3 id="spam-consequences">Spam Prevention Policy</h3>

* **Point Nullification:** Any activity marks earned through generic, repetitive, or low-effort comments will be voided during final evaluation.
* **Repeat Offenses:** Persistent low-effort spamming on peer repositories or community groups will result in a penalty on the author's final community score.
