<h1 id="submissions-reviews-overview">Submissions & Code Reviews</h1>

Understand how code reviews are conducted at NGCBD, why peer code reviews matter for your engineering career, and how to properly submit your project for the bi-monthly league.

---

<h2 id="review-process">1. How Project Review Works</h2>

At NGCBD, a code review goes far beyond checking if the code simply compiles or runs. Submissions undergo a comprehensive architectural and design evaluation based on real-world engineering standards.

<h3 id="review-pillars">Core Evaluation Pillars</h3>

* **Code Optimization & Performance:** Evaluation of code efficiency, avoidance of unnecessary re-renders or heavy loops, low memory footprint, and clean architectural patterns.
* **Bug Minimization:** Assessment of overall stability, edge-case handling, and defensive programming practices.
* **UI/UX & Accessibility:** Review of visual polish, smooth interaction states, responsive layouts, and user experience standard compliance.
* **Documentation Standards:** Inspection of the repository README, setup instructions, architecture breakdown, and API references.
* **Code Efficiency:** Recognition of concise, elegant code implementations that solve complex problems without unnecessary bloat.

---

<h2 id="interview-value">2. Value of Code Review in Job Interviews</h2>

In technical hiring, candidates who demonstrate structured code reviews and public peer feedback significantly outperform those who only share unreviewed repositories.

<h3 id="hiring-impact">Why Interviewers Value Reviewed Projects</h3>

* **Proof of Production Readiness:** Showing that your code has undergone thorough peer inspection proves that you understand code maintainability, clean architecture, and industry standards.
* **Constructive Feedback Handling:** Participation in code reviews demonstrates soft skills, such as receiving critique and iterating on architectural improvements—a key trait sought by senior engineering leads.
* **Verifiable Engineering Depth:** A reviewed repository with transparent commits and detailed review notes serves as strong Proof of Work during technical interviews.

---

<h2 id="why-showcase">3. Why Developers Should Showcase Their Work Here</h2>

Building complex projects in isolation often leads to lack of meaningful technical feedback or user adoption. NGCBD provides a dedicated ecosystem to solve this problem.

<h3 id="community-benefits">Key Showcase Advantages</h3>

* **High-Signal Technical Audience:** When non-technical audiences view advanced software, critical engineering depth often goes unnoticed. Showcasing to a developer-only community ensures your technical choices and effort are genuinely appreciated.
* **Meaningful Technical Suggestions:** Receive actionable suggestions on optimization, security, refactoring, and architectural design from fellow core builders.
* **User Adoption & Visibility:** Gain immediate users, testers, and potential contributors for your open-source software within the community.

---

<h2 id="how-to-submit">4. How to Submit Your Project</h2>

Submissions must be completed within the designated bi-monthly deadline window.

<h3 id="submission-requirements">Submission Requirements</h3>

* **GitHub Repository:** Code must be pushed to a public GitHub repository with complete commit history.
* **Professional README:** The repository must contain a clean, structured README file detailing the project scope, stack, setup instructions, and architecture.
* **Live Demo & Repository Link:** Submit the valid live demo URL alongside your GitHub repository link via the official submission portal.

For step-by-step instructions and submission guidelines, visit the <a href="/howtosubmit">How to Submit Guide</a>.
